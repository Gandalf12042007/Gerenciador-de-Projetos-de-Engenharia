FLUXO DE EXECUÇÃO:

1. INICIALIZAÇÃO
   └─ Browser carrega → Verifica localStorage (token)
      ├─ Se token existe → Valida com /api/auth/verify
      │  ├─ OK → Carrega aplicação
      │  └─ Inválido → Redireciona para login
      └─ Se não existe → Redireciona para login

2. AUTENTICAÇÃO
   └─ Login → POST /api/auth/login
      ├─ Sucesso → Retorna {access_token, refresh_token}
      ├─ Armazena em localStorage (criptografado)
      ├─ Inicia monitoramento de inatividade
      └─ Redireciona para projetos ou dashboard

3. OPERAÇÃO
   └─ User interage com app
      ├─ Requisições intercepadas por security-manager.js
      ├─ Headers automáticos (Authorization, X-Client-ID)
      ├─ Rate limiting verificado
      ├─ Resposta processada
      │  ├─ 401 → Logout automático
      │  ├─ 403 → Mostrar "Acesso Negado"
      │  └─ 200 → Processar dados
      └─ Ações registradas em auditoria

4. OFFLINE MODE
   └─ Sem internet (detectado)
      ├─ Service Worker intercepta requisições
      ├─ Serve de cache local (IndexedDB)
      ├─ Mostra indicador "OFFLINE"
      ├─ User pode ler dados cacheados
      └─ Quando volta online → Sincroniza

5. LOGOUT
   └─ User clica logout
      ├─ POST /api/auth/logout (seguro)
      ├─ Limpa localStorage
      ├─ Encerra Service Worker
      └─ Redireciona para login
